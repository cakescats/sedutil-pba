# Руководство пользователя CakesCats PBA

CakesCats PBA — предзагрузочная программа (pre-boot authorization) для SSD с
аппаратным шифрованием по стандарту TCG OPAL 2.0. Диск шифрует данные сам,
всегда. Пока он заблокирован, вместо содержимого он показывает компьютеру
маленький загрузочный образ: «теневой MBR», shadow MBR. Компьютер загружает
этот образ, вы вводите пароль, PBA разблокирует диск и перезагружает машину
уже в вашу систему.

## 1. Подойдёт ли ваш диск

- Нужен внутренний SATA- или NVMe-SSD с поддержкой **TCG OPAL 2.0**. Это
  большинство бизнес-моделей и многие потребительские: Samsung 9x0 PRO/EVO,
  Crucial, KIOXIA, WD, Kingston KC-серии и другие. Поддержку проверяет
  `sedutil-cli --scan` (раздел 3).
- **Не используйте диски в USB-боксах.** Многие USB-мосты неправильно
  передают команды OPAL, и диск можно испортить.
- Компьютер с UEFI. Secure Boot должен быть выключен: подписанные образы — в
  планах.
- Не меньше 160 МБ оперативной памяти. Это касается виртуальных машин:
  на 128 МБ ядро падает.
- Пароли диска — это пароли OPAL на самом диске. Ни PBA, ни образ их не хранят.

## 2. Что скачать

Со страницы [Releases](https://github.com/cakescats/sedutil-pba/releases)
(или из артефактов CI на вкладке Actions):

| Файл | Зачем |
|---|---|
| `cakes-pba-<версия>-default.img.gz` | Образ PBA для большинства. Есть сервисная консоль. |
| `cakes-pba-<версия>-hardened.img.gz` | Без сервисной консоли, сетевых драйверов и редактора меню загрузки. |
| `sedutil-cli-linux-x86_64` | Утилита настройки дисков для Linux, статическая: запускается на любом x86_64-дистрибутиве. |
| `*.sha256` | Контрольные суммы. |

```bash
sha256sum -c --ignore-missing cakes-pba-*-default.img.sha256
gunzip -k cakes-pba-*-default.img.gz
chmod +x sedutil-cli-linux-x86_64
sudo ln -s "$PWD/sedutil-cli-linux-x86_64" /usr/local/bin/sedutil-cli
```

Настраивать диск удобнее всего из Linux. Если на компьютере только Windows,
загрузитесь с любой live-флешки Linux, например Ubuntu: этого хватит.
`sedutil-cli.exe` 1.20 от DTA тоже совместим, но не умеет SHA-512 и пароли на
разделы.

## 3. Проверка без риска

**Поддерживает ли диск OPAL:**

```bash
sudo sedutil-cli --scan
```

После имени диска должна стоять `2`, например `/dev/nvme0  2  KIOXIA ...`.
`No` означает, что OPAL нет.

```bash
sudo sedutil-cli --query /dev/nvme0
```

У нового диска: `LockingEnabled = N`, `MBREnabled = N`.

У NVMe указывайте контроллер (`/dev/nvme0`), а не раздел или namespace
(`/dev/nvme0n1`).

**Загружается ли PBA на этом компьютере.** Запишите образ на отдельную
флешку. Всё содержимое флешки будет стёрто:

```bash
sudo dd if=cakes-pba-<версия>-default.img of=/dev/sdX bs=4M conv=fsync
```

Загрузитесь с флешки через boot menu прошивки. Должны появиться кот,
заголовок и список дисков, у вашего диска статус `not locked`.

**Перепишите PSID** с наклейки диска: 32 символа. Это единственный способ
вернуть диск, если пароль потерян, но он **стирает все данные**.

## 4. Установка

Сделайте резервную копию. Сами команды данные не стирают, но ошибка в пароле
или сбой питания посреди настройки — и до данных можно не добраться.

```bash
sudo sedutil-cli --initialSetup <пароль> /dev/nvme0
sudo sedutil-cli --loadPBAimage <пароль> cakes-pba-<версия>-default.img /dev/nvme0
sudo sedutil-cli --enableLockingRange 0 <пароль> /dev/nvme0
sudo sedutil-cli --query /dev/nvme0     # LockingEnabled = Y, MBREnabled = Y
```

- `--initialSetup` назначает владельца диска (SID) и администратора (Admin1)
  с этим паролем и включает теневой MBR.
- `--loadPBAimage` записывает PBA в теневой MBR. Это занимает до пары минут.
- `--enableLockingRange 0` включает блокировку всего диска. Она начинает
  действовать со следующего выключения питания.

Затем **выключите компьютер полностью**. Простая перезагрузка оставляет диск
под питанием и разблокированным.

Советы:

- Не используйте пароль `debug`: в default-образе так открывается сервисная консоль.
- Для пароля с хэшем PBKDF2-SHA512 добавляйте `-H sha512` к **каждой**
  команде `sedutil-cli` и включите `hash = sha512` в образе (раздел 8).
- Несколько дисков настраиваются так же, у каждого может быть свой пароль.
  PBA достаточно записать только на тот диск, с которого стартует прошивка.

## 5. Ежедневная работа

При включении появляется экран PBA:

```
            [кот]
   CakesCats Pre-Boot Authorization
   nvme0  KIOXIA KXG8AZN84T09   Z47F...   locked
     range 1                    16.0 GiB  locked, 5 tries left
   Password: ********
```

- **Введите пароль и нажмите Enter.** Пароль пробуется на всех
  заблокированных дисках.
- Если остались заблокированные диски или разделы, 3 секунды идёт отсчёт.
  Начните печатать следующий пароль: первая же клавиша останавливает отсчёт
  и становится первым символом пароля. Без нажатия система загрузится, а
  оставшиеся диски останутся заблокированными.
- **Esc** или пустой Enter, когда хотя бы один диск открыт, — загрузить
  систему сейчас.
- Неверный пароль: «No locked drive accepted this password». У каждого
  пароля на диске есть лимит попыток (на KIOXIA — 5) до следующего
  выключения питания.
- После разблокировки PBA делает тёплую перезагрузку. Диск при этом остаётся
  под питанием и открытым, и прошивка загружает систему.

**Меню загрузки.** Нажмите Esc сразу после выбора диска или флешки в
прошивке. Пункты:

- обычный запуск;
- **single CPU** (`nosmp`) — для машин, которые зависают до появления пароля;
- **service mode** — после разблокировки открыть консоль вместо загрузки ОС;
- **Reboot**;
- **UEFI firmware settings**.

**Сервисная консоль** (только в default-образе). Введите `debug` вместо
пароля или выберите service mode в меню. В консоли есть `sedutil-cli`, журнал
PBA лежит в `/tmp/pbaerror.log`. `exit` возвращает к вводу пароля. Консоль
можно отключить или закрыть отдельным паролем (раздел 8).

## 6. Смена паролей

```bash
sudo sedutil-cli --setAdmin1Pwd <старый> <новый> /dev/nvme0
sudo sedutil-cli --setSIDPassword <старый> <новый> /dev/nvme0
```

Меняйте оба пароля: SID — владелец диска, Admin1 — тот, что вводится в PBA.

Перевести существующий пароль с SHA1 на SHA-512 одной командой пока нельзя:
`-H` применяется сразу к старому и новому паролю. Схема хэша выбирается при
первоначальной настройке.

## 7. Разделы со своими паролями

OPAL может запирать части диска (диапазоны, обычно до 8) отдельными паролями.
Например, рабочий раздел открывается только вторым паролем. Admin1 остаётся
главным паролем и может открыть всё.

```bash
sudo sedutil-cli --setupPartitionRanges nvme0n1p2 <пароль A> <Admin1> /dev/nvme0
```

**Данные в этих разделах будут потеряны**: диапазон получает новый ключ.
Разметьте и отформатируйте разделы заново после команды.

В PBA сначала вводится Admin1, затем пароли разделов, по одному или общий на
несколько. Подробно — в [partitions.md](partitions.md).

## 8. Настройки

Настройки лежат в `/etc/cakes-pba.conf` внутри образа. Большинство из них
можно переопределить в меню загрузки (`EFI/BOOT/grub.cfg` на образе) через
`cakes.<ключ>=<значение>`. Полный список — в
[configuration.md](configuration.md). Основные:

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `timeout` | `3` | Сколько секунд ждать следующий пароль. `0` — сразу грузить ОС, `-1` — ждать, пока не откроется всё. |
| `hash` | `sha1:75000` | Схемы хэша: `sha1`, `sha512` или обе (`sha512,sha1`). |
| `reboot` | `warm` | Тёплая перезагрузка, чтобы диск не потерял питание. |
| `service` | `on` | Сервисная консоль: `on`, `off` или `password` (с `service_hash`, его делает `tools/mkservicehash.py`). |
| `ranges` | `none` | Пробовать ли пароли разделов до пароля Admin1. |

Чтобы поменять ключ в готовом образе без пересборки, правьте `grub.cfg` на
FAT-разделе образа **до** `--loadPBAimage`:

```bash
mkdir m && sudo mount -o loop,offset=1048576 cakes-pba-*-default.img m
sudo sed -i 's/reboot=warm"/reboot=warm cakes.timeout=10"/' m/EFI/BOOT/grub.cfg
sudo umount m
```

Свой логотип и свои значения в `cakes-pba.conf` требуют пересборки:
`scripts/build.sh --logo logo.png`. Конструктор образов — в планах.

## 9. Сон и гибернация

PBA работает только при холодной загрузке. Что будет во сне, зависит от того,
снимает ли компьютер питание с диска:

| Режим | Результат |
|---|---|
| **Гибернация (S4)**, Fast Startup в Windows | Работает: загрузка идёт через PBA, вводите пароль, система продолжает работу. |
| **S3 (Suspend to RAM)** | На проверенном десктопе (Ryzen 7800X3D) слот M.2 обесточивается, и диск после сна заперт — **с оригинальным образом DTA тоже**. ОС получает ошибки чтения. На некоторых ноутбуках диск остаётся под питанием, и всё работает. |
| **Modern Standby (S0ix)** | Работает, если диск во сне не уходит в D3cold. |

Рекомендации, пока нет помощников для ОС:

- **Windows**: проверьте сон на своей машине. Если после пробуждения система
  виснет, используйте гибернацию вместо сна (`powercfg /h on`, «Гибернация» в
  меню питания).
- **Linux**: `cat /sys/power/mem_sleep`. Если стоит `[deep]`, то есть S3,
  используйте гибернацию или `s2idle`. Утилита, которая сохраняет ключ в ядре
  (`sed-opal`) и открывает диск после S3, — в планах.

Результаты проверок собираются в [sleep-matrix.md](sleep-matrix.md).

## 10. Обновление PBA

```bash
sudo sedutil-cli --loadPBAimage <Admin1> cakes-pba-<новая версия>-default.img /dev/nvme0
```

Делайте это из системы, когда диск уже открыт. Перед загрузкой образа или
разблокировкой диска из работающего Linux **отмонтируйте теневой FAT**, если
рабочий стол смонтировал его сам (метка `CAKESPBA`): `udisksctl unmount -b ...`.
Иначе устаревший кэш FAT может записаться поверх реальных данных.

## 11. Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| PBA зависает до ввода пароля | Esc → **single CPU**. Не помогло — откройте issue и укажите модель, CPU и версию BIOS. |
| «failed (locked out, power cycle)» | Исчерпан лимит попыток. Выключите компьютер полностью (на ноутбуке иногда нужно подождать), включите, введите правильный пароль. |
| Система не грузится после ввода пароля | Загрузитесь с флешки с PBA: она видит диск как `locked`. Введите пароль, и после тёплой перезагрузки прошивка загрузит систему с диска. |
| `NO_SESSIONS_AVAILABLE` в sedutil-cli | Сессия зависла (процесс прервали посреди команды). `sudo sedutil-cli --stackReset /dev/nvme0` или подождать до 15 минут. |
| Windows не видит диск после пробуждения | Это сон S3, см. раздел 9. |
| Забыт пароль | Только `--yesIreallywanttoERASEALLmydatausingthePSID <PSID> /dev/nvme0`. **Это стирает все данные.** |
| Нужно выключить блокировку | Раздел 12. |

## 12. Отключение шифрования

Данные сохраняются:

```bash
sudo sedutil-cli --disableLockingRange 0 <Admin1> /dev/nvme0
sudo sedutil-cli --setMBREnable off <Admin1> /dev/nvme0
```

После этого диск больше не запирается, PBA не показывается. Чтобы полностью
снять владение диском, выполните `--revertNoErase <Admin1>`, затем
`--revertTPer <SID>`, строго в этом порядке. Без первой команды
`--revertTPer` стирает диск.

## 13. Что PBA защищает, а что нет

**Защищает:**

- выключенный компьютер, украденный ноутбук или вынутый диск: без пароля
  данные недоступны. Ключи хранит и применяет сам диск.

**Не защищает:**

- **включённый компьютер.** Диск открыт, пока у него есть питание, в том числе
  во время сна, если питание не снимается.
- **образ PBA от чтения.** Теневой MBR может прочитать кто угодно, поэтому в
  образе нет секретов. Изменить его можно только с паролем Admin1.
- **от загрузки без Secure Boot.** Злоумышленник с физическим доступом может
  загрузить свою систему, хотя данные диска без пароля ему всё равно не прочитать.

**default и hardened:**

- В default есть сервисная консоль и редактируемое меню загрузки. Это удобно,
  и данные без пароля так не получить, но это лишние возможности для
  человека у клавиатуры.
- Hardened их убирает. Его выбирают, когда за компьютером могут оказаться
  чужие люди.
